# Sprut.hub: Отправка сообщений в Telegram через Relay (notify-service)

Глобальный сценарий для платформы умного дома **Sprut.hub**, который предоставляет надежную функцию отправки текстовых сообщений в Telegram. 

Использует архитектуру «реле» (промежуточных шлюзов) с поддержкой резервирования, повторных попыток (retry) и кастомных API-ключей. Идеально подходит для тех случаев, когда встроенный объект `Notify` в глобальных сценариях работает нестабильно.

## Возможности
- 🔄 **Поддержка резервных серверов (Relay)**: Если основной шлюз не отвечает, скрипт автоматически переключится на следующий.
- 🔁 **Повторные попытки (Retry)**: До 5 попыток отправки при временных сбоях сети.
- 🔑 **Безопасность**: Поддержка кастомных API-ключей (`X-API-Key`) для каждого шлюза.
- 📢 **Мультиканальность**: Возможность отправки в несколько каналов Telegram одновременно (через запятую).
- 🏷 **Тегирование**: Автоматическое добавление подписи (тега) в конце сообщения, чтобы понимать, через какой именно сервер ушло сообщение.

## Установка

1. В интерфейсе Sprut.hub перейдите в раздел **Сценарии** -> **Глобальные сценарии**.
2. Создайте новый глобальный сценарий.
3. Скопируйте в него весь код из файла `scenario_global_send_tg_relay.js`.
4. Сохраните сценарий.

## Настройка

В начале файла `scenario_global_send_tg_relay.js` находится массив `RELAYS`. Настройте его под свои серверы.

```javascript
const RELAYS = [
    {
        // Основной сервер
        url:      "http://x.x.x.x:8448",
        api_key:  "ВАШ_API_КЛЮЧ",
        channels: "telegram_my_notify",
        tag:      "\n[notify-h2]"
    },
    {
        // Резервный сервер (сработает, если первый недоступен)
        url:      "https://backup.example.com:8443",
        api_key:  "КЛЮЧ_РЕЗЕРВНОГО_СЕРВИСА",
        channels: "telegram_my_notify",
        tag:      "\n[relay-h2]"
    }
];
```

Параметры конфигурации:
- url — базовый URL вашего шлюза (без /send).
- api_key — ключ авторизации для этого шлюза.
- channels — ID канала (или несколько ID через запятую).
- tag — текст, который будет добавлен в конец каждого сообщения (удобно для отладки).

## Использование в других сценариях
После установки и сохранения глобального сценария, функция sendNotifyToTG становится доступна во всех остальных сценариях вашего хаба.

## Пример 1: Блочный сценарий
Создайте обычный сценарий.

В блоке действий выберите «Блок кода».

Вызовите функцию:
```
global.sendNotifyToTG("Привет! Это тестовое сообщение из Sprut.hub.");
```

## Пример 2: Передача массива строк

```
global.sendNotifyToTG([
    "⚠️ Внимание!",
    "Устройство 'Робот-пылесос' не в сети.",
    "Проверьте питание."
]);
```

## Как это работает под капотом
1. Скрипт берет первый сервер из массива RELAYS.
2. Формирует JSON-запрос с channel_id, message и parse_mode: "Markdown".
3. Отправляет POST-запрос по адресу URL/send.
4. Проверяет ответ. Если статус 200 OK и в теле есть "status": "success", отправка считается успешной.
5. Если произошла ошибка (сеть, 500-я ошибка сервера), скрипт делает паузу в 1 секунду и пробует снова (до 5 раз).
6. Если все попытки через первый сервер провалились, скрипт берет следующий сервер из массива RELAYS и повторяет процесс.

### Обратите внимание:
В файле `scenario_global_send_tg_relay.js` убедитесь, что в самом низу или в начале файла нет лишних вызовов вроде `sendNotifyToTG("Тест")`. Глобальный сценарий должен только **объявлять** функцию, чтобы она не срабатывала при каждом перезапуске хаба. 

Если вы планируете использовать этот репозиторий как публичный, не забудьте удалить из кода реальные `api_key` и IP-адреса, заменив их на заглушки (как в примере выше).
